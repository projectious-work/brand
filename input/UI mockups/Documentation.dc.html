Deploying your first pipeline

This guide walks through defining a pipeline, attaching a policy check, and running it end to end. It assumes you have an agent connected to a workspace.

Before you start

You need a workspace with at least one connected agent, and the projectious CLI installed locally.

1. Define the pipeline

Pipelines are declared in YAML. Create pipeline.yaml in your project root:

# pipeline.yaml
name: onboarding-audit
trigger: on_document_upload
agent: auditor-v3
steps:
  - validate_schema
  - policy_check
  - deploy_staging

2. Add a policy check

Attach an existing policy so every run is audited before it deploys:

$ projectious policy attach onboarding-audit --policy data-retention-v2
ⓘ

Policies are versioned. Attaching a new version does not affect runs already in progress.

3. Run and audit

Deploy the pipeline and watch the first run in the console. Every step is logged and the auditor agent reviews the output before it reaches production.

$ projectious run --pipeline onboarding-audit
✓ Config validated against schema v3.2
✓ Policy check: 12 rules passed
● Deploying to staging...
